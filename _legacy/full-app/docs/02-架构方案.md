## 2. 一个必须先定死的架构决策：估价算在哪一端

**结论：估价计算留在前端，后端只提供数据。**

理由：

1. `core/valuation/` 是纯函数，无副作用、无网络、无平台依赖 → 放前端可离线运行，拍照前就能算
2. 若后端也算一遍，会出现**两份实现**，公式一改就要同步两处，是 bug 温床
3. `AGENTS.md` 第 4 节明确规定该层"不读配置、不碰网络"——放后端反而违反现有约束
4. 用户在结果页拖动溢出滑块时，前端本地即时重算，**零网络往返**

代价：系数更新需要走 `GET /coefficients`（见下）；离线时用内置快照兜底。这个代价是可接受的。

> 备选方案（暂不采纳）：估价全放服务端。将来若需要"防篡改估值"或"服务端批量出报告"再迁移，届时前端 `core/` 可以直接复用为服务端的计算模块（同语言）。

│   ├── lib/                      [新增] 基础设施
│   │   ├── api/

## 4. 接口契约

三个端点，全部只读（MVP 不做账号体系，见 `AGENTS.md` 第 6 节）。

### 4.1 `GET /api/v1/materials`

返回面料价格表。**每条强制带出处与数据等级**（落实 `AGENTS.md` 第 5 节红线）。

```json
{
  "updatedAt": "2026-09-26T08:00:00+08:00",
  "items": [
    {
      "key": "cotton_twill",
      "label": "全棉轧染纱卡",
      "unit": "米",
      "unitPrice": 15.6,
      "spec": "148cm 20S×16S、128×60 全工艺环保",
      "grade": "official",
      "source": {
        "org": "绍兴市发展和改革委员会（绍兴e价通）",
        "url": "https://jgjg.sx.gov.cn/",
        "period": "2026-06-22",
        "fetchedAt": "2026-09-26T08:00:00+08:00"
      }
    }
  ]
}
```

`grade` 取值：`official`（政府公布）／`index`（指数报价）／`estimate`（行业估算）。
前端必须把 `estimate` 如实标注，不得冒充满官方。

### 4.2 `GET /api/v1/coefficients`

返回品类系数（**不含**溢出比例——那一项由用户决定）。

```json
{
  "version": "2026-09-26",
  "categories": {
    "apparel_outerwear": {
      "label": "外套",
      "processingFee": 45,
      "designRate": 0.25,
      "premiumRate": 0.60,
      "overflowHint": 0.55,
      "auxiliaryRate": 0.18
    }
  }
}
```

`overflowHint` 只是滑块默认位置，不是强制值。

### 4.3 `POST /api/v1/recognize`

识别接口。输入图片或文本，输出**候选结果 + 置信度**，前端必须让用户确认后才进入估价（`AGENTS.md` 第 3 节第 5 条）。

请求：

```json
{ "image": "<base64>", "hint": "可选，用户补充的文字描述" }
```

响应：

```json
{
  "needConfirm": true,
  "result": {
    "category": "apparel_outerwear",
    "brandTier": "known",
    "fabricKey": "cotton_twill",
    "materialAmount": 1.8,
    "confidence": 0.82,
    "source": "vlm",
    "provider": "qwen-vl-max",
    "elapsedMs": 3200
  },
  "candidates": [
    { "category": "apparel_outerwear", "confidence": 0.82 },
    { "category": "apparel_knit", "confidence": 0.11 }
  ]
}
```

**降级链（必做）**：VLM 超时/失败 → 文本兜底（关键词匹配）→ 完全失败则返回错误，前端引导用户手动录入。任何一环都不允许让整个流程崩溃。

### 4.4 鉴权与防滥用

MVP 无用户体系，但接口要防刷：

- 前端生成匿名设备 ID（首次启动写入本地存储），随请求头发送
- 后端按设备 ID + IP 限流（参数照搬调研模板：识别类 30 次/分钟）
- 图片请求限制体积上限（建议 5MB）与格式白名单

## 5. 环境变量与密钥

### 5.1 前端（可见，严禁放敏感信息）

```
# .env.development
EXPO_PUBLIC_APP_ENV=development
EXPO_PUBLIC_API_URL=http://192.168.x.x:3000

# .env.production
EXPO_PUBLIC_APP_ENV=production
EXPO_PUBLIC_API_URL=https://api.example.com
```

规则：`EXPO_PUBLIC_*` 会被打进包体，**任何密钥都不得出现在这里**。

### 5.2 后端（不可见）

```
# .env.development.local（本地开发，不进仓库）
VLM_API_KEY=...
VLM_MODEL=qwen-vl-max
PORT=3000
LOG_LEVEL=DEBUG
```

照搬调研模板的三个做法：

1. `.env.{env}.local` → `.env.{env}` → `.env.local` → `.env` 优先级链
2. 环境感知覆盖（dev 开 DEBUG，prod 收紧日志与限流）
3. **密钥强度校验：启动时拒绝空值/占位值，直接抛错退出**

`.gitignore` 必须包含 `.env*.local`。

## 6. 依赖选型

### 6.1 前端

**必装（第二阶段）**

| 包 | 用途 |
|---|---|
| `expo-router` | 文件路由（替换手写页面切换） |
| `@tanstack/react-query` | 服务端数据缓存与重试 |
| `axios` | HTTP 传输 |
| `zod` | 校验后端返回结构 |
| `expo-image-picker` | 拍照 / 相册选取 |
| `expo-image` | 图片显示与缓存 |
| `react-error-boundary` | 页面级错误兜底 |

**暂缓（需要时再装）**

| 包 | 原因 |
|---|---|
| `zustand` | 当前状态简单，先用 React 内置 |
| `react-native-mmkv` | 先问：只需要存设备 ID，AsyncStorage 够用 |
| `i18next` | 单人中文项目不需要 |
| `nativewind` | StyleSheet 目前够用 |

**不装**

| 包 | 原因 |
|---|---|
| `moti` / `reanimated` | 动画需求未出现 |
| `@shopify/flash-list` | 列表规模远未到性能瓶颈 |
| husky / commitlint / maestro | 单人项目，收益低于成本 |

### 6.2 后端

**框架（三选一，待拍板）**

| 选项 | 优势 | 劣势 |
|---|---|---|
| **Hono** | 极轻、快、TS 原生、Web 标准 | 生态比 Express 小 |
| **Fastify** | 性能好、插件体系成熟、文档全 | 略重 |
| **NestJS** | 结构最规范、适合长期演进 | 对小服务偏重、学习曲线陡 |

**必装**：`zod`（校验）、`dotenv`（配置）、抓取用原生 `fetch`、定时任务用 `node-cron`
**暂不装**：数据库/ORM（MVP 不存用户数据）、Redis（内存缓存够用）、Docker（本地跑不必要）

## 8. 待拍板（阻塞对应阶段）

| # | 决策 | 影响范围 | 建议 |
|---|---|---|---|
| 1 | 后端语言：Node vs Python | 阶段 2 起全部后端代码 | **Node（Hono）**——与前端同语言，`core/valuation` 可双向复用，一人维护成本最低 |
