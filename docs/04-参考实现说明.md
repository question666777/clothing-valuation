# 参考实现说明

`core/` + `config/` 共约 2500 行，**零平台依赖**（无 `wx.` / `window` / `react` / `process.env`），纯粹是「数据 + 计算」，可以直接 `require` 复用。

## 结构

```
core/valuation/
  index.js    对外唯一入口：estimate(itemInfo) → priceRange
  model.js    纯计算：把已定价的用料算成五段 + 区间（仅 95 行）
config/
  fabric.js        纤维规格档表 + 面料表 + 辅料比例 + 克重表（每条带 source + period + grade）
  brands.js        品牌库（品牌 × 系列，毛利率派生倍率）
  coefficients.js  品类加工费、设计费率、溢出比例
  index.js         取数口：定价、单位换算、自动补部位等
```

## 数据流

```
输入（纤维成分 + 品类 + 重量 + 品牌）
  → config 层：成分 → 查单价（无价降级）；重量 → 换算千克；补系统默认部位
  → core 层：纯函数算五段 + 区间
  → 输出 priceRange + 拆解
```

## 从哪读起

1. 先看 `docs/01` 理解五段
2. 再看 `core/valuation/model.js`（才 95 行，就是全部计算公式）
3. 最后看 `config/fabric.js`，理解「每条数据都带出处」的写法

## 几个设计要点

- **`core/` 不读配置、不碰网络**：它是纯计算，输入必须已定价。这样估值逻辑可以单独测试、单独复用。
- **定价属于 `config/`，计算属于 `core/`**：分层边界清晰，换数据源 / 换公式互不影响。
- **缺价就 `null` + 降级**，绝不用 0 占位（0 会被当成「真价格」参与计算，是静默错值）。
- **单位换算只在一处**：`config/index.js`。界面和 core 都不许自己乘一遍——两份换算迟早不同步。

## 怎么套到别的领域

这套思路不限于衣服。核心是三步：

1. 把「这个领域的东西值多少钱」拆成 N 段加法，**成本段和加价段分开**
2. 每一段找官方数据源，找不到就诚实标 `estimate` / 留空
3. 缺数据降级、不许填假数、每笔钱可下钻

换领域时：

- 改 `config/`（换成你的数据表和系数）
- `core/model.js` 的公式形状基本通用（成本段求和 + 加价段加成）
- **关键是「口径」**：想清楚哪些是成本、哪些是加价，别糊在一根加法线上（见 `docs/01`）
