# 数据从哪来

## 铁律：不许凭常识填价

任何进计算的价格 / 费率，必须满足其一：

1. **有权威出处** → 写明机构 + URL + 数据期 + 抓取日期
2. **没有出处** → 标 `estimate`，界面如实标注「估算」
3. **取不到价** → `unitPrice: null` + 降级，**不许拿 0 冒充有效价**

这条铁律的背后逻辑：**「缺数据」会走降级、界面能看见；「编一个数」是静默给错，谁都发现不了。**

## 两个维度要分清

| 要什么 | 谁能给 | 说明 |
|---|---|---|
| 纤维成分和含量 | 水洗标（国标强制） | GB/T 29862 强制耐久性标签标注；线上销售页面也必须公示，且与实物一致 |
| 材料单价 | 官方指数 / 监测 | 品牌官网**查不到**采购价，只能查官方大宗成交价 |
| 品牌溢价率 | 上市公司年报 | 由综合毛利率派生：`加价倍率 = 1 / (1 − 毛利率)`，禁止手填 |

**结论：品牌官网提供的是「成分」，不是「价格」。** 模型要的是「成分（水洗标）+ 单价（官方指数）」相乘，不许因为官网查不到价格就退回凭常识填价。

## 两个最容易踩的认知坑

1. **官方没有「面料名」报价档**：牛仔布、雪纺、摇粒绒、帆布是**商品名或织法**，不是纤维，官方指数里查不到价格。识别到这类词只能**推成分再按纤维价算**，不能编一个「牛仔布 28 元/米」。
2. **同一纤维按规格档价差巨大**：同为棉，长绒棉 137 级 26.72 元/kg vs 细绒棉 2227B 15.84 元/kg（差 69%）；同为羽绒，90% 白鹅绒 984 vs 70% 灰鸭绒 369（差 167%）。**按纤维名给一个均价，误差比模型里所有系数加起来都大。**

## 缺数据怎么办

- **纤维有价** → 查官方有没有这个规格档；没有 → 登记进缺源名单，**逐条写原因**，不许顺手填个数
- **辅料单价** → 全部留空（`null`），这是正常状态，不是「没做完」
- **识别命中但查不到价** → 等于没识别，必须如实告知，不许静默丢弃

## 抓取：现状与两条教训

**现状**：价格取发版快照，抓取入口（`_legacy/full-app/server/`）已建、棉花信息网已抓通并对拍一致。**实时化不是本方法论的必要条件**——若要每天自动更新，部署两条路二选一：微信云开发（免域名免备案）或自建后端（需 ICP 备案），把抓取脚本挂上去定时跑即可。

两条实测换来的教训：

1. **首页能抓 ≠ 价格能抓**。六个政府站 HTTP 全 200、页面都拿到了，但第一轮探测的「可见价格片段」全是 0——政府站普遍把数据放在网络层之后（JS 渲染 / 登录墙 / 动态接口）。**判定可行性必须下钻到「能不能解析出数字」，不能只看状态码和字节数。**
2. **官方源可访问性有环境依赖**。本机不通不代表服务器出口也不通，反之亦然。正式的可用性判定必须在**将来真正跑抓取的那个环境**里做，本机结论只能当初筛。
