# 踩坑记录

17 条真实踩过的坑。每一条的共同点是：**不报错、不降级，但结果就是错的**，而且谁都发现不了。

## 识别相关

1. **短别名做子串匹配必误伤**：`RalphLauren` 含 `HLA`，拿别名当子串会把「Ralph Lauren 衬衫」认成海澜之家。→ 先全等，再包含且别名 ≥4 字取最长。
2. **从商品描述找品牌，只用品牌正名做子串，不碰别名**：别名字典和正名匹配是两回事，分工不同别混用。
3. **「识别命中」≠「能算出价」**：识别产出的 key 必须在配置表里找到，否则命中等于落空。官方没这种档就**改识别口径**，别用「补数据」解决。
4. **识别结果的每一类输出都要被消费**：识别返回品类 / 纤维线索 / 品牌档位，`brandTier` 曾被界面整个丢掉——奢侈档设计费率 0.60 vs 普通 0.12，**差 5 倍**，一条「古驰大衣」会按普通品牌算出来。

## 数据与计算相关

5. **漏组成项被级联放大**：漏算辅料 → 低估 15%。组装必须收进一个函数，界面不许自己拼。
6. **分母不完整 = 静默缩放器**：填「棉 80%」等于按八折出价；没价的成分被跳过 → 单价腰斩。声明占比与可定价占比要**分开报**。
7. **显示口径 ≠ 计算口径**：换计价方式只改 `mode` 没改 `unit`，界面显示的和实际算的就不一样。两侧一起改，换回去重置数值。
8. **默认档不许取极值**：档位表按从贵到便宜排，取「第一个有价」就是顶格（羊绒虚高 223%、羊毛 264%、棉 69%）。默认取价格中位。
9. **砍品类要同时改三处**：品类系数 + 数据表（克重 / 单件重量 / 辅料比例）+ 识别词表。漏任何一处都不是「少个功能」，是「多一条通往错数的静默通道」。

## 界面相关

10. **改被界面引用的字段名会静默弄坏界面**：改字段前先 grep 界面层。
11. **「点了没反应」有三个成因**：热区 <40px / 处理函数抛异常 / 绑定名不存在。表现一样，要分头守。
12. **「数据层齐全」≠「用户能核对」**：单价与出处写在数据字段里，但 `picker` 只渲染 `label`，那个字段从头到尾没被任何模板引用过。**加数据字段之后要单独确认它真的被渲染了。**
13. **有价就必须在界面上看得见来源**：取不到价要如实写「暂无权威报价」，不许留空——留空在界面上就是整行消失，用户以为这条成分没了。
14. **删输入项前先问：它是不是成本组成项**：是 → 转成系统默认值并汇报，不能直接删。
15. **列表重排后旧下标不能跨列表复用**：列表按品类重排后，同一个 3 指向的就不是同一家。换列表必须**按 key 重映射**，否则选择静默串到别人。

## 工程相关

16. **换品牌必须把系列归零**：拿 A 的系列套 B 是静默串味。同一状态变化（换品类）若有两条路径各写一份实现，必然漂移 → 抽成一个共用函数。
17. **Windows 嵌套 `spawnSync` 同一 node.exe 会 EBUSY**：校验脚本用进程内 `require` 代替子进程。开发者工具导入的是 `miniprogram/` 子目录，不是仓库根（根的 app.json 是别的配置，没有 `pages` 字段）。
